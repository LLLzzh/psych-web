# 对话历史长页面与右侧时间轴设计

> **已废弃：** 本方案已由
> `docs/superpowers/specs/2026-07-27-conversation-switcher-design.md`
> 取代。新方案点击浮窗条目后替换主对话区内容，不再把全部历史会话拼成长页面。

## 目标

在桌面端对话页中，将当前用户的全部历史会话按时间顺序合并为一个可连续滚动的长页面，并在页面右侧中部增加会话时间轴导航。每个历史会话对应一个导航点，标签直接截取该会话的第一条用户发言；点击导航点后平滑滚动到长页面中的对应会话。

本功能不做语义关键词提取，不调用新的模型接口，也不改变移动端布局。

## 范围

### 包含

- 分页加载全部历史会话列表。
- 分页加载每个历史会话的全部消息。
- 将历史会话渲染为一个连续的消息长页面。
- 为每个会话生成一个稳定的页面锚点。
- 在桌面端右侧中部展示与 Figma 节点 `6433:5346` 一致的白色圆角悬浮卡片。
- 在卡片中展示纵向时间轴、会话导航点和第一条用户发言的截取文本。
- 点击导航项时平滑滚动并短暂高亮目标会话。
- 根据长页面滚动位置同步高亮当前会话导航点。
- 保持当前实时会话可正常发送、接收和自动滚动。

### 不包含

- 后端接口改造。
- AI 关键词提取或中文分词。
- 会话搜索、筛选、删除、重命名。
- 移动端时间轴导航。
- 修改独立的“往日记录”页面。

## 信息架构与布局

### 长页面

桌面端 `ChatArea` 的主滚动容器同时承载历史会话和当前实时会话：

1. 历史会话按 `createTime` 升序排列，较早会话在上，较新会话在下。
2. 每个会话作为一个独立 `section`，使用 `conversationId` 作为稳定键和锚点。
3. 会话内部消息按 `index` 升序排列，继续使用现有用户/老师消息气泡样式。
4. 相邻会话通过留白和轻量分隔线区分，不增加占空间的复杂标题。
5. 当前实时消息作为最末尾的“当前会话”区段；若它的 `conversationId` 已存在于历史结果中，则只保留一个区段，实时消息优先覆盖重复消息，避免重复展示。

移动端继续只展示当前实时消息，不加载或渲染完整历史长页面。

### 右侧时间轴卡片

- 仅在桌面端且至少存在一个可展示会话时出现。
- 固定在对话内容区域右侧中部，不随消息长页面滚动。
- 参考 Figma：约 `265 × 232px`、白色背景、圆角、柔和浅蓝阴影。
- 卡片内部可滚动，避免会话数量较多时撑高页面。
- 每个导航项包含一个圆点和一行截取文本。
- 文本来源为该会话按 `index` 排序后的第一条学生消息；去除首尾空白并压缩连续空白，显示约 12 个中文字符，超出使用省略号。
- 没有学生消息时退回使用会话 `brief`；两者都为空时显示“未命名对话”。
- 当前会话导航点使用紫蓝渐变色和较高对比度文字，其他点使用浅灰紫色。

## 组件边界

### `useMergedConversationHistory`

新增专用 hook，负责桌面端历史数据编排：

- 获取全部会话列表页，按 `conversationId` 去重。
- 对每个会话获取全部消息页，按 `index` 去重并排序。
- 限制并发历史请求数量，避免会话较多时瞬间发出大量请求。
- 暴露统一的加载状态、整体错误和单会话错误。
- 提供重试单个失败会话的方法。
- 组件卸载时忽略过期请求结果，避免旧请求污染新页面状态。

该 hook 不复用 `useConversationRecords` 的“单选中会话”状态，因为后者一次只维护一个会话详情，与本功能的多会话同时展示目标不同。

### `ConversationTimeline`

新增纯展示/交互组件：

- 接收会话摘要数组、当前激活 `conversationId` 和点击回调。
- 只负责卡片、时间轴、导航点、截取文本和无障碍状态。
- 导航项使用 `button`，提供清晰的焦点样式及 `aria-current`。

### `ChatArea`

扩展现有组件：

- 桌面端渲染历史会话区段与当前实时会话区段。
- 管理每个会话锚点的 DOM 引用。
- 响应时间轴点击，调用主滚动容器的 `scrollTo`，并考虑顶部内边距。
- 通过 `IntersectionObserver` 或滚动位置计算同步当前激活会话。
- 目标区段滚动完成后添加约 1.5 秒的淡紫色轮廓/背景高亮。
- 持有锚点、激活会话和短暂高亮状态，并在内部直接渲染 `ConversationTimeline`；父层只负责提供历史聚合数据和当前会话 ID。

## 数据流

1. `ChatPage` 根据 `isDesktopLayout` 决定是否启用历史聚合 hook。
2. hook 分页取回全部会话列表。
3. hook 为每个会话分页取回全部消息，生成 `MergedConversation` 数据。
4. `ChatArea` 依次渲染各会话区段，并为每个区段登记锚点。
5. `ConversationTimeline` 从同一份聚合数据生成导航项。
6. 用户点击导航项后，`ChatArea` 平滑滚动到对应锚点并高亮。
7. 用户手动滚动时，视口中的会话区段更新当前导航点。
8. 当前实时消息变化时，仅更新末尾当前会话区段；历史区段不重新抓取。
9. 新会话创建后，将其立即加入末尾导航；结束会话后刷新会话列表，使后端最终历史与本地状态对齐。

## 加载与错误处理

- 初次加载历史时不阻断当前对话输入和 WebSocket 连接。
- 已加载的会话立即渲染，后续会话可渐进补齐，不等待所有请求结束。
- 单个会话加载失败时，在对应区段展示简短失败提示和“重试”按钮；其他区段保持可用。
- 会话列表加载失败时，隐藏时间轴并在消息区域顶部展示非阻塞错误提示和重试入口，当前实时对话仍可使用。
- 空历史时不显示时间轴，仅显示当前实时会话。
- API 返回重复页数据时按会话 ID 和消息 `index` 去重。

## 滚动规则

- 初次打开且存在当前实时消息时，保持现有滚动到底部行为。
- 仅历史数据逐步加载时，不强制把用户从正在阅读的位置拉到底部。
- 用户点击时间轴后，暂时抑制消息自动滚底，直到目标滚动完成。
- 当前实时消息新增且用户原本接近底部时继续自动滚底；用户正在查看旧会话时不强制跳回底部。
- 导航激活判定以主滚动容器上方约三分之一处对应的会话区段为准，避免边界抖动。

## 视觉规则

- 沿用项目现有 Tailwind v4、浅色/深色主题与消息气泡设计，不新增 UI 依赖。
- 浅色主题卡片使用白色/半透明白色、`15px` 左右圆角和浅蓝阴影。
- 深色主题使用半透明黑色与 `backdrop-blur`，保持与现有桌面聊天面板一致。
- 卡片宽度约 `265px`；右侧保留安全间距，聊天消息内容区相应增加右内边距，避免遮挡消息。
- 卡片高度最大约 `232px`，内部滚动条保持细且低对比度。
- 时间轴激活态沿用项目的 `#8686FF` 至 `#96C0FF` 紫蓝色系。

## 可访问性

- 导航列表使用带标签的 `nav`。
- 每个会话项使用原生按钮，支持键盘聚焦与 Enter/Space 激活。
- 激活项设置 `aria-current="location"`。
- 平滑滚动遵循 `prefers-reduced-motion`；用户偏好减少动画时改为即时定位，并取消闪烁式强调。

## 验证

### 自动检查

- `npm run lint`
- `npm run build`

### 手工验证

- 使用 mock 数据确认 5 个历史会话均合并到长页面，顺序正确且消息不重复。
- 确认每个时间轴点的文字来自对应会话第一条学生发言。
- 点击首个、中间和最后一个导航项，确认滚动目标与高亮正确。
- 手动滚动长页面，确认时间轴激活点同步且不抖动。
- 模拟超过卡片高度的会话数量，确认卡片内部滚动且消息区域不被遮挡。
- 模拟单个历史接口失败，确认其他会话仍可查看并可单独重试。
- 在实时接收消息时确认：接近底部会自动滚动，阅读旧会话时不会被拉回底部。
- 强制移动端布局，确认历史时间轴不出现且原有聊天功能不回归。
- 分别检查浅色和深色桌面主题。

## 验收标准

- 桌面端能够在同一长页面连续查看全部历史会话和当前实时会话。
- 每个历史会话在右侧时间轴中仅对应一个导航点。
- 导航文字直接截取第一条用户发言，不进行语义提取。
- 点击任意导航项能可靠定位到对应会话区段。
- 长历史、分页、部分失败和实时消息更新不会导致重复内容或意外滚动。
- 移动端行为保持不变，项目 lint 与构建通过。
