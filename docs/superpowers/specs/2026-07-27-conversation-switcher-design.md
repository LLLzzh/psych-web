# 桌面端右侧会话切换浮窗设计

## 状态

已确认，取代 `2026-07-16-conversation-timeline-design.md` 中“合并历史长页面并滚动定位”的方案。

## 目标

在桌面端对话区右侧中部增加会话切换浮窗。每个历史项代表一次完整会话；点击后，主对话区通过柔和动效替换为该会话的完整消息。当前展示的会话在浮窗内高亮。

功能必须保留当前实时会话的连接和消息状态。查看历史记录时不允许向旧会话发送消息，也不能因实时消息到达而打断阅读。

## 范围

### 包含

- 桌面端右侧中部会话切换浮窗。
- 分页加载历史会话列表，按需加载并缓存单个会话详情。
- 当前会话固定在列表底部并始终可返回。
- 当前项高亮、实时新消息提示点、列表内部滚动。
- 历史会话只读状态及“返回当前对话”入口。
- 会话切换淡出、轻微纵向位移和淡入动效。
- 浅色、深色主题及键盘、减少动效支持。

### 不包含

- 移动端浮窗；移动端继续使用现有“对话记录”页面。
- 修改后端接口。
- 恢复旧方案中的历史长页面、锚点定位或滚动同步。
- 搜索、筛选、删除、重命名或编辑历史会话。
- 将消息发送到已结束的历史会话。

## 核心交互

### 浮窗条目

- 一条历史记录对应一次完整历史会话。
- 历史项标题直接使用会话列表接口返回的 `brief`；为空时显示“未命名对话”。
- 当前会话作为一个本地合成条目固定在最底部；标题使用当前会话第一句非空用户发言，没有发言时显示“新对话”。
- 历史项按时间从旧到新排列；加载更旧分页时插入列表顶部。
- 当前展示项使用紫蓝渐变轨道和高对比度文字，其余项使用浅灰色。
- 记录超过浮窗最大高度时仅浮窗内部滚动；切换后自动将激活项滚入可视区域。

### 切换会话

1. 用户点击未缓存的历史项。
2. 页面保留现有消息，覆盖轻量半透明加载态，不先清空内容。
3. 客户端按需请求该会话详情的全部分页。
4. 请求成功后，现有内容在约 `220ms` 内淡出并轻微下沉。
5. 替换消息数据，新内容从上方轻微位移，在约 `260ms` 内淡入。
6. 浮窗高亮同步过渡到目标项，消息滚动位置置顶。

点击已缓存历史项时跳过网络加载，直接执行切换动效。点击已经激活的条目不重复请求或播放整段切换动效。

### 当前与历史模式

- 当前模式展示 `chatStore.messages`，底部保留现有文字和语音输入。
- 历史模式展示选中会话的缓存详情，不修改或覆盖 `chatStore.messages`。
- 历史模式下底部输入区替换为“返回当前对话”按钮，明确标注历史记录只读。
- 返回当前模式时直接恢复保留的实时消息并滚动到底部。
- 查看历史期间若当前会话收到新消息，页面不自动切回；当前条目显示轻量提示点。用户返回当前会话后清除提示点。
- 当前会话尚未创建或没有消息时，仍显示并高亮底部“新对话”条目。

## 视觉设计

- 浮窗固定在桌面端对话内容区域右侧中部，不随消息列表滚动。
- 参考图使用约 `250–265px` 宽、最大约 `258px` 高、`18–20px` 圆角。
- 浅色主题使用高透明度白色、浅蓝紫阴影和轻量背景模糊。
- 深色主题使用现有半透明黑色面板语言，保持文字对比度。
- 主消息区增加右侧安全内边距，确保气泡和浮窗不重叠。
- 条目为一行省略文本，右侧短轨道表示状态；激活项下方可带细紫蓝渐变强调线。
- 历史模式显示轻量“历史记录 · 只读”标记。
- “返回当前对话”使用紫蓝渐变胶囊按钮，位于原输入区附近。

## 组件与职责

### `useConversationSwitcher`

新增桌面端专用 hook，负责：

- 复用现有会话列表 API 和分页语义。
- 维护当前显示模式和选中历史会话 ID。
- 按需获取被选中会话的全部消息分页。
- 按 `conversationId` 缓存已完成的会话详情。
- 按会话 ID 和消息 `index` 去重并稳定排序。
- 管理请求版本，确保快速连续点击时只有最后一次选择生效。
- 暴露列表/详情加载状态、错误、重试和加载更多操作。
- 在桌面布局关闭时停止浮窗交互，不影响移动端。

复用现有会话 API、响应类型和排序/去重规则，但不复用
`useConversationRecords` 的全局选中状态。聊天页的列表、当前/历史双模式和详情缓存保存在
`useConversationSwitcher` 内，避免独立记录页的选中状态污染实时聊天页。

### `ConversationSwitcher`

新增纯展示和交互组件，负责：

- 渲染历史项、合成的当前项、激活态和实时新消息提示点。
- 提供浮窗内部滚动、顶部加载更多触发和激活项自动可见。
- 使用原生 `button`，设置 `aria-current`、加载和错误状态。
- 不直接请求数据，不持有聊天消息。

### `ChatArea`

扩展现有组件，负责：

- 接收当前或历史模式的展示消息。
- 保留现有消息气泡视觉，并适配历史消息数据类型。
- 管理退出、替换、进入三个切换阶段。
- 当前模式维持既有的消息自动滚底行为。
- 历史模式载入后滚动到顶部，不因实时消息更新改变位置。

### `ChatPage`

负责组合：

- 仅在 `isDesktopLayout` 时启用 switcher hook 和浮窗。
- 将实时消息、历史展示消息、模式和交互回调传给 `ChatArea`。
- 根据模式渲染现有 `InputArea` 或“返回当前对话”入口。
- 监听当前实时消息数量变化，为历史模式设置提示点。
- 结束当前会话后刷新历史列表，并建立新的本地“新对话”项。

## 数据与状态

建议状态模型：

```ts
type ConversationView =
  | { mode: "current" }
  | { mode: "history"; conversationId: string };

type HistoryCacheEntry = {
  status: "loading" | "ready" | "error";
  messages: ConversationMessageItem[];
  error: string | null;
};
```

- `chatStore.messages` 始终是当前实时会话的唯一真源。
- 历史详情缓存以 `conversationId` 为键，仅在当前页面生命周期内保留。
- 历史列表以 `conversationId` 去重，展示时按 `createTime` 升序。
- 当前合成项不写入后端历史列表；如列表响应意外包含当前 `conversationId`，展示层必须去重。
- 快速连续选择通过递增请求版本或 `AbortController` 实现“最后一次选择生效”。

## 分页规则

- 历史列表继续使用现有分页接口；首次加载最近一页。
- 因展示顺序为旧到新，首次页内部升序排列，当前项置底。
- 用户滚动到浮窗顶部时加载更旧一页并插入顶部，同时补偿 `scrollTop`，保持视觉位置不跳动。
- 选中历史会话后逐页拉取其完整消息，按 `index` 去重并升序排列；全部详情成功后才切换展示。
- 详情正在加载时允许用户选择另一项；旧请求结果不能覆盖新选择。

## 加载与错误处理

- 历史列表初次加载不阻塞 WebSocket、当前消息或输入。
- 列表失败时浮窗显示简短错误和“重试”，当前对话保持可用。
- 详情加载时保留现有消息，覆盖非阻塞加载态。
- 详情失败时不切换展示；浮窗或轻提示提供重试。
- 某一历史详情失败不影响其他缓存会话。
- 历史为空时仍显示当前合成项。
- 结束对话后的列表刷新失败不清除已有列表，允许手动重试。

## 动效与可访问性

- 默认退出动画约 `220ms`：透明度降低、向下位移约 `8–10px`，可带极轻微模糊。
- 默认进入动画约 `260ms`：从上方 `8–10px` 回到原位并淡入。
- 浮窗激活态使用较短的颜色、背景和轨道过渡。
- 遵循 `prefers-reduced-motion`：减少动效时使用即时替换或仅极短淡入，不使用位移和模糊。
- 浮窗使用带可访问名称的 `nav`，条目使用 `button`，支持 Enter/Space。
- 激活项设置 `aria-current="location"`；加载、错误和未读状态有文本或无障碍标签，不能只依赖颜色。
- 键盘焦点样式在浅色和深色主题下都清晰可见。

## 验证

### 自动检查

- `npm run lint`
- `npm run build`

项目目前没有单元测试脚本，本功能不额外引入测试框架。

### 手工检查

- 桌面浅色、深色主题下浮窗位置、阴影、对比度和消息避让正确。
- 当前项始终位于底部；历史项旧到新排序，长列表内部滚动。
- 加载旧分页时浮窗视觉位置不跳动。
- 点击首个、中间、最后一个历史项均展示对应完整消息。
- 首次加载显示轻量加载态，缓存后再次切换不重复请求。
- 快速连续点击多个条目时最终只展示最后一次选择。
- 详情加载失败时保留原内容并可重试。
- 历史模式只读，“返回当前对话”恢复实时消息和输入。
- 查看历史时收到实时新消息不会跳转，当前项出现提示点。
- 结束会话后历史列表刷新，新的“新对话”当前项保持在底部。
- 强制移动端时浮窗和历史只读入口均不出现，原有聊天与记录页无回归。
- 开启系统“减少动态效果”后没有明显位移或模糊动画。

## 验收标准

- 桌面端对话区右侧中部存在与参考图一致的会话切换浮窗。
- 每个历史项代表一次完整会话，标题使用后端 `brief`。
- 点击历史项通过已确认的 A 动效替换主对话内容，激活项同步高亮。
- 历史记录只读，当前实时消息和连接不被覆盖或中断。
- 历史阅读期间收到实时消息不强制切换，用户可看到提示并主动返回。
- 列表与详情分页、缓存、快速切换和局部失败不会产生重复内容或错误覆盖。
- 移动端保持原行为，lint 与构建通过。
